3. New functionality
3.1 Another script class
We're in need of another type of script, and a generator for it. 
The major difference for this script compared to the current script type we have implemented, is that
this script creates pooled samples in some box-groups and invividual samples in a other box-groups,
depending on the spec. Each journal case is X number of induvidually pipetted samples that will also
be pooled to a single well in the pooled box-group.
The script would read a .txt or .csv file (make it accept both) journal system export to 
determine the number of samples in total which will be presented (in same fashion/position as 
standard script) but NOT changable in the script screen. The file will consist of one column
without a header. The structure of this file will me something like:

1
1
2
2
3
3
3
3
3

In this file, 1, 2, 3 represents different journal cases, and the number they're repeated is the
number of samples from the system, INCLUDING the pooled sample which we generate in the upcoming
pipetting process. This means the number of samples we're putting into the machine is 1 less
for each journal case than presented in the file. Case 1 has 1 sample, case 2 has 1 sample, case 
3 has 4 samples, etc. In reality, the rows are containing differing repetitions of text/number values, 
not neccesarily just integers. So the function deciphering this needs to be robust. 

So differences and new functions for the script screen: 
-The script reads a .csv or .txt file in the directory specified in config. If there's more than 1
.csv and/or .txt file in the directory, the script doesn't start but rather warns us 
"Flere lister i DIRECTORY, rydd opp i disse og prøv igjen" (replace DIRECTORY with the directory). 
The warning can be crossed out, or dissapears after 10 seconds.
-Number of samples not an input, only a display of the value calculated from the file. 
-Number of journal cases/pooled samples displayed below number of samples ("Antall sampleprøver")
-Start and stop value from the journal system export file (first and last value) displayed below 
these. Example: "Saker: "2025-06-K1999" til "2025-06-K2005""
-Box-groups with pooled samples would have the pooled samples added, which would in most cases be
fewer and in all cases be the same as number of unique journal cases. So we have two different 
sample counts being added to their respective start positions and visualisations. 

The generator would be quite identical with our standard script, except we have a checkbox for 
pooled samples, "Samleprøve-boks", in the box-group specification part of the generator. We also
need to specify our directory for the journal system export (folder, not file). Early in the spec.
